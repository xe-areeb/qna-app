# EventPulse - Technical Specification

> Live quiz engagement and audience rankings for events. EventPulse is the product name; the underlying generic product type is a **quiz leaderboard app**.

## Approach

The app is being **extended, not rebuilt**. The existing Next.js + Convex scaffold is preserved; the data model gains an `events` table and existing tables become **event-scoped** via `eventId`. Convex function names are preserved where possible; their argument shapes evolved to require (or accept) `eventId`.

### Deferred concerns

- **Admin auth**: an MVP shared-code gate is in place (see "Admin gate (MVP)" below) but it is **not** real auth. There is no per-user identity, no role separation, no rotation/audit. Replace with Convex Auth + role check before deploying.
- **Visitor auth**: deferred. Visitors are identified by `visitorName` (display label) plus a stable client-generated `visitorIdentifier` (e.g. localStorage UUID). Convex Auth integration can replace `visitorIdentifier` later without schema churn.
- **Per-event analytics first**: dashboards/metrics start at the event scope (queries filter by `eventId`). Cross-event aggregates can be added later via additional queries.

## Event-based Architecture

```
events ──┐
         ├── questions       (eventId)
         ├── quizSessions    (eventId, visitorIdentifier)
         └── answers         (eventId, sessionId, questionId)

Browser (Next.js)
   │  visitorIdentifier (client-generated, persisted)
   ▼
Convex React client ──► Convex deployment
   ├── per-event queries (live leaderboard, active questions, event-by-slug)
   └── per-event mutations (sessions, answers, admin event/question CRUD)
```

Event scope is the primary partitioning axis. Listing, leaderboard, and analytics queries take an `eventId` (or `slug` resolved to an `eventId` via `events.getActiveEventBySlug`).

## Convex API - Implemented exports

All functions marked **(admin-gated)** require `adminCode: string` as their first argument and call `assertAdmin` before doing any work. See "Admin gate (MVP)" below.

| File | Export | Kind | Behavior |
|------|--------|------|----------|
| `adminAuth.ts` | `assertAdmin` | helper | Compares `adminCode` against `process.env.ADMIN_ACCESS_CODE`. Throws `ConvexError` if the env var is unset or the code mismatches. Imported by every admin-gated function. |
| `adminAuth.ts` | `verifyAdminCode` | mutation | One-shot validator for `/admin`'s unlock form. Throws on mismatch / unset env, returns `{ ok: true }` on success. |
| `adminAuth.ts` | `isAdminConfigured` | query | Public probe → `boolean` reflecting whether `ADMIN_ACCESS_CODE` is set on the deployment. Lets the UI explain "admin code is not configured" without leaking the value. |
| `events.ts` | `listEvents` | query | All events; optional `status` filter using `by_status`. |
| `events.ts` | `getActiveEventBySlug` | query | Returns the event for a slug if its `status === "active"`, else `null`. |
| `events.ts` | `adminCreateEvent` | mutation **(admin-gated)** | Inserts; rejects duplicate slug. |
| `events.ts` | `adminUpdateEvent` | mutation **(admin-gated)** | Patches event fields; bumps `updatedAt`. |
| `events.ts` | `adminArchiveEvent` | mutation **(admin-gated)** | Sets `status = "archived"`. |
| `questions.ts` | `listActiveQuestions` | query | Active questions for `eventId`, sorted by `order`. Uses `by_event` + JS filter today (compound `by_event_active` is reserved for typed codegen later). |
| `questions.ts` | `adminCreateQuestion` | mutation **(admin-gated)** | Inserts question for an event; validates 4 options + `correctAnswerIndex` range. |
| `questions.ts` | `adminUpdateQuestion` | mutation **(admin-gated)** | Patches fields; validates as above. |
| `questions.ts` | `adminDeleteQuestion` | mutation **(admin-gated)** | Deletes by id. |
| `quizSessions.ts` | `createQuizSession` | mutation | Idempotent start/resume for `(eventId, visitorIdentifier)`. Returns `{ sessionId, status }` so callers can route to `/quiz` (in-progress) or `/results` (completed). |
| `quizSessions.ts` | `completeQuizSession` | mutation | Validates `(eventId, sessionId)`; idempotent. Tallies correct answers, derives `score` / `percentage` / `rating` / `timeTaken`, patches the session to `completed`. |
| `quizSessions.ts` | `getLeaderboard` | query | `eventId` optional for backward compat; returns `[]` if missing. Otherwise completed sessions for that event, sorted by score DESC then `timeTaken` ASC. Uses `by_event` + JS filter on `status === "completed"`. **TODO**: make `eventId` required when UI selects an event. |
| `quizSessions.ts` | `getQuizResult` | query | `{ sessionId }` → session document fields used by `/results` and `/quiz` (visitor name, status, score, totalQuestions, percentage, rating, timeTaken, completedAt, eventId). Returns `null` if missing. |
| `quizSessions.ts` | `getSessionAnsweredCount` | query | `{ sessionId }` → number of answers persisted; drives quiz progress and resume. |
| `quizSessions.ts` | `getSessionRank` | query | `{ sessionId }` → `{ rank, total }` (1-based) for completed sessions, using the same `score DESC, timeTaken ASC` ordering as `getLeaderboard`. Returns `null` for missing or in-progress sessions. Powers the rank chip on `/results`. |
| `analytics.ts` | `getEventAnalytics` | query **(admin-gated)** | `{ eventId }` → `{ totalCompleted, totalInProgress, averageScore, averagePercentage, highestScore, fastestTime, totalActiveQuestions }`. `fastestTime` is the fastest `timeTaken` *among the highest scorers* (matches leaderboard tie-break ordering). Aggregates are computed in-memory per request - fine for demo volumes; denormalise once volumes grow. |
| `analytics.ts` | `getQuestionAnalytics` | query **(admin-gated)** | `{ eventId }` → list of `{ questionId, order, question, totalAnswers, correctCount, correctPercentage }` for the event's active questions, sorted by `order`. Powers the per-question correctness bars on `/admin/analytics`. |
| `answers.ts` | `submitAnswer` | mutation | Validates session/question/event consistency, range-checks `selectedAnswerIndex`, rejects duplicates per `(sessionId, questionId)`, persists `isCorrect` server-side. Returns `{ answerId, isCorrect }` (UI must **not** display `isCorrect` mid-quiz). |
| `seed.ts` | `seedDemoEvent` | mutation **(admin-gated)** | Idempotent. Creates (or reuses) the event with slug `demo-event` (title `EventPulse Demo`, status `active`). On reuse, also patches `title` / `description` back to the constants if they have drifted (so a rename in `convex/seed.ts` propagates by re-running the mutation). Inserts any of the 15 sample questions whose `order` is missing for that event. Returns `{ eventId, createdEvent, createdQuestions, existingQuestions }`. |
| `seed.ts` | `resetDemoEventResponses` | mutation **(admin-gated)** | Looks up the event with slug `demo-event`. **Deletes** every `quizSessions` row + every `answers` row scoped to that event. **Preserves** the event itself and all of its questions (active or inactive). Graceful no-op when the demo event hasn't been seeded yet (`{ deletedSessions: 0, deletedAnswers: 0, eventFound: false }`). On success returns `{ deletedSessions, deletedAnswers, eventFound: true }`. After the call, analytics, leaderboard, and `/display` show their empty states until a new visitor finishes the quiz. |

The Convex CLI populates `convex/_generated/api.{js,d.ts}` and `convex/_generated/dataModel.d.ts`; import from `@/convex/_generated/api` for `api.*` and `@/convex/_generated/dataModel` for `Id<TableName>` / `Doc<TableName>`. ### Visitor identity (temporary)

`visitorIdentifier` is built client-side as ``${eventId}:${slug(visitorName)}``, where `slug()` lowercases, trims, replaces whitespace with `-`, and strips non-alphanumeric characters. The pair `(eventId, visitorIdentifier)` is the natural key - two visitors sharing an event AND a normalized name will collide and share an attempt. Acceptable for demos; **replace with Convex Auth before any public competition.**

## Frontend Routes & UX

- **Loading / error**: `LoadingPlaceholder`, `ErrorPlaceholder` for inline, and `RouteError` for full-card direct-route errors with a primary CTA (`Start from home`) and optional secondary action.
- **`ConvexClientProvider`**: Always wraps the tree; uses `NEXT_PUBLIC_CONVEX_URL` or a placeholder URL at build time so SSR/prerender succeeds.
- **`ConvexEnvBanner`**: Warns when `NEXT_PUBLIC_CONVEX_URL` is unset (queries use `"skip"`).
- **`SiteChrome`**: Client wrapper that decides whether to render the global header / footer / Convex env banner. It hides chrome on `/display` (and any `/display/*` sub-route) so the projection screen takes the full viewport with no flash on direct visits - `usePathname` is read on both server and client. The footer is also hidden on `/` and `/quiz` (any `/quiz/*` sub-route) so the kiosk landing screen and the active question fit common tablet / laptop viewports without scrolling past the primary CTAs; other routes keep the compact footer.
- **`LeaderboardPanel`**: Accepts an optional `eventId: Id<"events">` prop; reads from `getLeaderboard`. Renders two layouts (compact for `/leaderboard`, oversized for `/display`), with rank chips, top-3 medals, percentage, rating, and `Mm Ss` formatted time.
- **`/`** *(client)*: loads `getActiveEventBySlug({ slug: "demo-event" })` plus `listActiveQuestions` (for the question count blurb), captures display name (validated min 2 chars + must contain alphanumerics), shows event title + a "How it works" instructions card, calls `createQuizSession`, then routes to `/quiz?event=demo-event&sessionId=…` (in-progress) or `/results?sessionId=…` (already completed). Start button is disabled while loading or if the name is invalid.
- **`/quiz`** *(client, Suspense)*: reads `event` + `sessionId` from search params; loads event, session result, ordered active questions, and `getSessionAnsweredCount`. Shows one question at a time with a `Question N of M` strip + percent-complete + accessible `role="progressbar"`. Options are large lettered tap targets; the selected option uses an emerald ring. `submitAnswer` advances `localIndex`; on the final answer the page calls `completeQuizSession` and replaces history with `/results`. The button text cycles **Next question → Saving… → (final) Submit final answer → Completing quiz…**, blocking double-submits. A guarded effect handles **resume mid-completion** (all answered but session still in-progress) and shows a dedicated "Completing your quiz…" card while `completeQuizSession` runs. Direct hits without `event` + `sessionId` show `RouteError` ("No quiz in progress" + Start from home).
- **`/results`** *(client, Suspense)*: reads `sessionId`; renders score / total / percentage / rating / time taken (`Mm Ss`) from `getQuizResult` and a **rank chip** (`#X of N`) from `getSessionRank`. The card uses a rating-tinted gradient frame (Champion→amber, Excellent→emerald, Good→sky, Try Again→zinc). CTAs: View leaderboard, Open projection screen (new tab), Back to home. Direct hits without `sessionId` show `RouteError` ("No result to show" + Start from home).
- **`/leaderboard`** *(client)*: resolves `demo-event` → `eventId` and feeds `LeaderboardPanel`. Adds inline CTAs to take the quiz and open the projection screen.
- **`/display`** *(client, no chrome)*: dark/projection layout, oversized typography, top **10** rows, top-3 medals, live updates via `useQuery`. Includes a small "Exit projection" link back to `/leaderboard`.
- **`/admin`** *(client)*: Entry point for the demo admin gate. Locked → renders an unlock form whose submit calls `verifyAdminCode` and, on success, writes the code to `sessionStorage` via `useAdminUnlock`. Unlocked → renders sub-nav cards (Questions, Analytics) plus a "Lock admin" button that wipes the cached code. Probes `isAdminConfigured` to surface "admin code is not configured on the server" up front.
- **`/admin/questions`** *(client, gated by `AdminGate`)*: Event picker (defaults to first active event), selected-event header (title/status/slug), question list (active only, ordered), create form (4 options + radio for correct answer + order + active), **inline edit per row** (`Edit` button replaces the read-only card with `EditQuestionForm`; `Save` / `Cancel` exit edit mode), hard-delete button per row, **Create demo event** button (UI label; backed by `seed.seedDemoEvent`), **Reset responses** danger-zone (`ResetDemoButton`). Only one row can enter edit mode at a time - the other rows' Edit/Delete buttons are disabled while a row is being edited so the data model and undo story stay simple. All protected mutation calls (`seedDemoEvent`, `adminCreateQuestion`, `adminUpdateQuestion`, `adminDeleteQuestion`) are invoked with the unlocked `adminCode`. `eventId` is preserved automatically by `adminUpdateQuestion` (the mutation doesn't accept `eventId`).
- **`/admin/analytics`** *(client, gated by `AdminGate`)*: Event picker (same logic as `/admin/questions`), reads `analytics.getEventAnalytics` and `analytics.getQuestionAnalytics` (both with `adminCode`). Includes the **Reset responses** danger-zone (`ResetDemoButton`).

### `ResetDemoButton`

Shared client component (`components/reset-demo-button.tsx`) used by both admin pages. Takes a required `adminCode` prop, calls `api.seed.resetDemoEventResponses({ adminCode })`, gates with a browser `confirm`, and renders idle / loading / success / error states inside a destructive red card. Wording explicitly states what is deleted (sessions + answers for `demo-event`) versus preserved (the event and all of its questions). After a successful reset, every live `useQuery` (analytics, leaderboard, `/display`) refreshes itself to its empty state without a manual reload.

## Admin gate (MVP)

A deliberately small access layer suitable for MVP / client demos. It is **not** a replacement for proper auth - there are no per-user accounts, no role separation, no audit trail, and no rotation tooling beyond `npx convex env set`.

**Server side (Convex):**

- `convex/adminAuth.ts` exports the synchronous helper `assertAdmin(adminCode)` which compares the supplied code against `process.env.ADMIN_ACCESS_CODE` and throws a `ConvexError` on mismatch (or when the env var is unset).
- The same module exposes:
  - `verifyAdminCode({ adminCode })` mutation - used by `/admin`'s unlock form.
  - `isAdminConfigured()` query - public boolean probe so the UI can show "not configured on server" instead of a confusing error.
- Every protected function takes `adminCode: v.string()` as its first argument and calls `assertAdmin` before reading/writing data. Currently protected:
  - `seed.seedDemoEvent`, `seed.resetDemoEventResponses`
  - `events.adminCreateEvent`, `events.adminUpdateEvent`, `events.adminArchiveEvent`
  - `questions.adminCreateQuestion`, `questions.adminUpdateQuestion`, `questions.adminDeleteQuestion`
  - `analytics.getEventAnalytics`, `analytics.getQuestionAnalytics`
- Public/visitor-facing functions (visitor session lifecycle, leaderboard, results) are intentionally **not** gated - visitors must be able to play without an admin code.

**Client side (Next.js):**

- `lib/use-admin-unlock.ts` exposes `useAdminUnlock()`, a hook backed by `sessionStorage` (key `qna:admin-code`). It tracks `code`, `hydrated`, `isUnlocked`, plus `unlock(code)` / `lock()`. Hydration-aware so the UI never flashes the wrong state during SSR / first paint.
- `components/admin-gate.tsx` is the wrapper used by admin routes. While `useAdminUnlock` hydrates it shows a "Checking admin access…" placeholder; locked → renders `RouteError` with a CTA back to `/admin`; unlocked → calls its `children` render-prop with `{ adminCode, lock }`.
- `app/admin/page.tsx` is the unlock entry point and the "session" management screen (Lock admin button) once unlocked.
- The unlocked `adminCode` is forwarded to every protected mutation/query call from `/admin/questions`, `/admin/analytics`, and the shared `ResetDemoButton`.

**Configuration:**

- Local dev / production deployments: `npx convex env set ADMIN_ACCESS_CODE <your-code>` per Convex deployment. Do **not** prefix with `NEXT_PUBLIC_` - the code stays server-side; the client only ever holds the value the user typed in.
- `.env.example` documents the variable but never actually sets it in `.env.local` (Convex env vars live on the deployment, not in Next.js's env loader).
- If the admin needs to rotate the code, run `npx convex env set ADMIN_ACCESS_CODE <new-code>` again. Existing `sessionStorage` codes will start failing on the next protected call; visitors should re-unlock at `/admin`.

## Deployment

The app deploys as **two independent pieces** - Convex (backend) and Cloudflare Pages (frontend, via static export). Full step-by-step + smoke-test checklist lives in `README.md` → "Deployment" and `project.md` → "Deployment Checklist". Quick reference:

1. **Convex** (backend):
   - `npx convex deploy` - push schema + functions to the prod deployment.
   - `npx convex env set ADMIN_ACCESS_CODE <code> --prod` - set the prod admin secret. (Re-run to rotate.)
2. **Cloudflare Pages** (frontend, static export):
   - Build command: `npm run build`. Output directory: `out/`. Node version: `20`.
   - Env vars (Production + Preview): `NEXT_PUBLIC_CONVEX_URL` (= prod Convex HTTPS URL), `NODE_VERSION=20`.
   - **Why static export**: every route prerenders to static HTML and all data fetching is client-side via the Convex React client. No SSR / route handlers / server actions / dynamic params, so `@opennextjs/cloudflare` is unnecessary and would only add complexity.

To preview the production export locally before pushing: `npm run build && npm run preview` (serves `out/` on `http://localhost:4173`). `next start` does **not** work with `output: "export"`.

## Security Notes

- The MVP admin gate is a **shared-secret check, not real auth**. `assertAdmin` only compares strings; there is no rate limiting, lockout, audit trail, or per-user identity. Replace with Convex Auth + role check before any production deployment that exposes admin tooling.
- `ADMIN_ACCESS_CODE` lives in the **Convex deployment env**, never on the client. The Next.js client only ever sees the value the visitor typed into `/admin`. `sessionStorage` is per-tab and trivially inspectable, but exposure to other origins is the same as any other in-page state.
- Leaderboard query (`quizSessions.getLeaderboard`) and `getQuizResult` / `getSessionRank` are intentionally readable by anonymous clients - these power the public visitor flow.
- `analytics.getEventAnalytics` and `analytics.getQuestionAnalytics` are **admin-gated** (`assertAdmin`) - they require the shared secret.
- Visitor identity relies on a client-supplied `visitorIdentifier`; treat as advisory until visitor auth lands. The deterministic `${eventId}:${slug(name)}` form means same name + same event = shared attempt - acceptable for demo, **not** for public competition.
- `submitAnswer` persists `isCorrect` server-side; the **frontend never displays correctness mid-quiz**. The result is only revealed after `completeQuizSession`.
